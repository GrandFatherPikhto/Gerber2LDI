# Gerber2LDI

Засветка фоторезиста лазером (LDI) по файлам Gerber: лазер 405 нм засвечивает резист
строка за строкой, включаясь и выключаясь по положению.

Конвейер: геометрия гербера → отрезки «вкл/выкл» по строкам → компенсация пятна,
зеркало, полярность, калибровка → задание для станка (G-code для прошивок семейства
GRBL). Промежуточного растра нет: картинка добавила бы только дискретизацию и память.

Состояние: ранняя разработка. Программа собирает и проверяет задание и пишет файл;
**на станке задание ещё не выполнялось** — всё, что так помечено ниже, не проверено.

## Что уже работает

```sh
gerber2ldi info layer.gbr                     # единицы, размер, апертуры, полярность
gerber2ldi raster layer.gbr -o layer.tif      # строки + превью в TIFF для глаз
gerber2ldi job layer.gbr --profile profiles/china_ldi_grbl.toml \
    --power <из полоски дозы> -o layer.nc     # программа для станка
gerber2ldi preview layer.nc -o layer.png      # что именно станок нарисует
gerber2ldi pattern bars   --profile P --power 0.05 -o bars.nc
gerber2ldi pattern dose   --profile P --from 0.02 --to 0.16 --count 6 -o dose.nc
gerber2ldi pattern square --profile P --power 0.05 -o square.nc
gerber2ldi pattern grid   --profile P --power 0.05 \
    --width-mm 50 --height-mm 40 --line-mm 0.2 --gap-mm 0.15 -o grid.nc
```

Мощность в примерах нарочно малая: первые платы засвечиваются на низкой доле, а рабочее
значение берётся из полоски дозы (шаг 9), а не с этой страницы.

Тестовые маски для MSLA-принтера, привязанные к пикселям, — отдельный скрипт, а не
команда пакета: `tools/msla_tests.py` (см. «MSLA-принтер: тестовые маски» ниже).

## Чего эта программа НЕ делает

* **Не выгружает герберы из KiCad.** Для этого есть командная строка самого KiCad
  (`kicad-cli pcb export gerbers`, `kicad-cli pcb export drill`); проект читает файлы,
  а не делает их.
* **Не выставляет рабочий ноль.** G54 — дело оператора: подвести головку к углу стола,
  названному в `profile.table.origin`, и послать `G10 L20 P1 X0 Y0` (или нажать
  «ноль» в программе-отправителе).
* **Не разговаривает со станком.** Ни порта, ни потоковой отправки: она пишет файл.
  Отправлять — UGS, LaserGRBL или Candle.
* **Не калибрует себя.** Штрихи, полоска дозы и квадрат засвечиваются и меряются вами,
  штангенциркулем и микроскопом; числа пишутся в файл калибровки. Сетка — вообще не
  замер, а тест покрытия.
* **Не ставит диагноз процессу.** Она отказывает там, где может доказать ошибку;
  остальное — таблица симптомов в конце.
* **Не делает процесс безопасным.** Экран, очки и кнопка стоп — на вашей стороне стола.

## Работа со станком

### 1. Герберы из KiCad

Выгрузить медь, контур платы и сверловку:

```sh
kicad-cli pcb export gerbers board.kicad_pcb -o gerbers/
kicad-cli pcb export drill board.kicad_pcb -o gerbers/
```

Дальше посмотреть, что пришло: `gerber2ldi info` печатает единицы, размер, число
апертур и фигур и есть ли светлая полярность (`%LPC*%`). Размер, не совпавший с
платой, — первое, что надо поймать.

*В этом проекте не прогонялось: обе строки `kicad-cli` — по документации KiCad, а не
из запуска здесь.*

### 2. Профиль и калибровка

`profiles/china_ldi_grbl.toml` — отправная точка: скопировать и поменять размер стола,
`machine.steps_per_mm_x/y`, `scan.row_step_um`, `scan.speed_mm_s`, `scan.overscan_mm`,
`laser.s_max`, `laser.usable_fraction`. Профиль описывает ТИП станка и лежит в git.

`machine.steps_per_mm_x` и `_y` — ответ вашего `$$`, строки `$100` и `$101`: сколько
микрошагов контроллер считает на миллиметр. Они обязательные, потому что
`scan.row_step_um` обязан быть ЦЕЛЫМ числом микрошагов по Y. При `$101 = 80` шаг/мм
один микрошаг — 12.5 мкм: 25 мкм строки — это 2 шага, а 20 мкм — 1.6, и такой профиль
**отклоняется** с обоими числами: строки легли бы через 12.5 и 25 мкм попеременно, и
засветка вышла бы полосами. Отрезки короче микрошага по X не отклоняются: программа
считает их и говорит строкой, потому что их края прилипают к ближайшему шагу.

Измеренная ошибка вашего экземпляра лежит рядом, в `profiles/<имя>.calibration.toml`:

```toml
[calibration]
scale_x = 1.002      # реальное / заданное
scale_y = 0.998
skew_deg = 0.1       # > 0: реальная ось Y наклонена к +X
spot_radius_um = 150 # измерено шаблоном bars
measured = 2026-10-21
```

Нет файла калибровки — предупреждение, приняты нейтральные значения (масштаб 1,
перекос 0). Нет замера пятна — **отказ** строить компенсацию; `--no-spot-compensation`
говорит вслух, что вы согласны на линию шире нарисованной.

### 3. Собрать задание

```sh
gerber2ldi job F_Cu.gbr --profile profiles/china_ldi_grbl.toml \
    --power 0.05 --frame Edge_Cuts.gbr -o top.nc
gerber2ldi job B_Cu.gbr --profile profiles/china_ldi_grbl.toml \
    --power 0.05 --side bottom --process etch-resist \
    --frame Edge_Cuts.gbr --place 20,30 -o bottom.nc
```

* `--frame` — контур платы, ОДИН И ТОТ ЖЕ файл для обеих сторон. Это прямоугольник, по
  которому рисунок зеркалится и ставится на стол, поэтому стороны ложатся друг на друга.
  Без него каждая сторона ставится по своей меди: для одной стороны это нормально, и
  программа об этом говорит — предупреждение называет `--frame` для второй стороны.
* `--side bottom` зеркалит рисунок: резист засвечивается с другой стороны.
* `--process` — для чего резист: `etch-resist` светит МЕДЬ (резист остаётся там, где
  медь), `plating-resist` светит ПРОМЕЖУТКИ. **Одна плата — один процесс**: у платы на
  травление травятся обе стороны, поэтому оба задания используют одно значение; разными
  они были бы только у платы, меняющей процесс между сторонами.
* `--power` — доля от модуля; выше `usable_fraction` — отказ, а не обрезка. `0.05` в
  примере — безопасное первое значение, настоящее берётся из полоски дозы.
* `--place X,Y` ставит начало полосы разгона в эту точку стола, а низ РАМКИ — на `Y`.
  Для обеих сторон — ОДИН `--place`. KiCad пишет отрицательные Y; программа ставит рамку
  на стол и проверяет весь проход вместе с разгоном против стола. Без `--place` рамка
  идёт в начало координат.
* каждая строка светится от одного разгона ПЕРЕД её первым засвеченным пикселем до одного
  разгона ПОСЛЕ последнего, всегда в +X, а строка, на которой нечего светить, не проезжается
  вовсе. Разгон выбирает люфт ремня в одну и ту же сторону каждый раз, и при этом ничего не
  сдвигается: `--frame` и `--place` ставят рисунок ровно как раньше — ушли только холостые
  концы строк.
* задание говорит, что это дало, — в stdout и в шапке `.nc`: `passes: 1234.5 mm exposed run
  (full-width would be 2345.6 mm, -47%), >= 4 min 06 s at 50 mm/s`, то есть рабочий ход
  против хода «во всю ширину». Время — НИЖНЯЯ граница: возвраты, ускорения и `M4/M5` в нём
  не посчитаны (скорости холостого хода в профиле нет).

**Стороны совпадают только через рамку и упор заготовки.** Засветить первую сторону,
перевернуть заготовку слева направо о тот же упор, засветить вторую. Камеры и совмещения
по отверстиям в этой программе нет: если заготовка между прогонами сдвинулась, стороны
не совпадут, и никакой файл этого не исправит.

### 4. Проверить перед засветкой

```sh
gerber2ldi preview top.nc -o top.png
```

На что смотреть: верх картинки — большее Y (вид сверху, как в GerbView); нижняя
сторона выходит зеркальной; медь против промежутков соответствует `--process`;
пропорции совпадают с платой. Превью можно построить и из гербера с профилем
(`preview layer.gbr --profile … -o layer.png`) — это показывает задание до файла.

### 5. Станок, один раз

Две настройки GRBL решают, что значат числа в файле; обе названы в его шапке, так что
файл никогда не двусмыслен:

* **`$32=1` — лазерный режим.** `M4`/`M5` переключают луч и без него. Но БЕЗ лазерного
  режима GRBL **останавливается на каждой смене `S`**: головка тормозит, луч горит,
  пока она ждёт, и каждое место смены мощности пересвечено. С `$32=1` мощность меняется
  на ходу.
* **`$30` = `laser.s_max` профиля** (1000 в китайском профиле). `S` — доля ИМЕННО от
  этого числа: меньший `$30` в прошивке делает `S600` больше задуманного, больший —
  меньше.

Проверить командой `$$`, выставить: `$32=1`, `$30=1000`.

*На станке не проверялось: шапку стережёт тест, а поведение контроллера с неверным
`$30` — дело контроллера.*

### 6. Перед каждым запуском

Рабочий ноль G54 — в углу стола, который назван в `profile.table.origin` (`front-left`).
Подвести головку над углом и в консоли отправителя:

```
G10 L20 P1 X0 Y0
```

(или кнопка «выставить ноль» в отправителе). Числа в программе — рабочие координаты;
проверка «внутри стола» сравнивает их с системой, которая должна существовать. Дальше:
плата ровно на вакуумном столе, фокус выставлен, первый проход на малой мощности.

### 7. Отправка

Готовый файл `.nc`, отправленный программой для GRBL: **UGS** (Universal Gcode Sender),
**LaserGRBL** или **Candle**. Что важно:

* потоковая отправка с «character counting» (отправитель держит несколько строк
  впереди), а не построчная с ожиданием после каждой;
* никаких преобразований в отправителе — ни масштаба, ни сдвига, ни «оптимизации», ни
  переупорядочивания: это файл координат, а не картинка.

*На станке не проверялось: ни один из трёх отправителей с этой программой ещё не
работал. Сам `gerber2ldi` порт не открывает.*

### 8. Безопасность

Лазер 405 нм — видимый фиолетовый, и глаз фокусирует его на сетчатке.

* **Экран** из оранжевого акрила на 405 нм вокруг рабочей зоны или **очки** с указанной
  оптической плотностью на 405 нм (OD4+). Выбирать по МАРКИРОВКЕ (диапазон должен
  включать 405 нм, а OD — быть указан), никогда по цвету линзы.
* **Обычные очки не защищают**: стекло пропускает 405 нм; «защитные очки» из
  хозмага про эту длину волны ничего не говорят.
* Первые проходы — на малой мощности; пробная засветка на обрезке, а не на плате.
* **Останавливать** кнопкой станка или сбросом в отправителе (`Ctrl-X` / reset), а не
  закрытием окна программы.
* Не оставлять лазер включённым, пока головка не движется.

*Здесь не проверялось: выбор экрана и очков — дело оператора; программа их не видит и
не управляет ими.*

Собственные сторожа программы скромные и настоящие: потолок мощности — отказ, и проход
вместе с разгоном обязан влезть на стол. Всё, что может погасить луч — концевики,
аварийная кнопка, сторожевой таймер — в прошивке и на станке: окно на ПК — обещание,
которое некому сдержать, пока движение уже началось.

### 9. Калибровка по шагам

1. `pattern bars --profile … --power 0.05 -o bars.nc` — засветить и проявить. Под
   микроскопом измерить ШИРИНУ засвеченной линии в группе 200 мкм: без компенсации линия,
   нарисованная шириной `w`, выходит `w + 2r`, значит
   `spot_radius_um = (измеренная − w) / 2`. Проверить по группе 150 мкм: обе группы должны
   дать одинаковый радиус. Этот радиус уже включает уход проявки — ровно то, что
   компенсация должна снять. Грубая проверка без микроскопа: самая узкая группа, у которой
   выжили И линии, И промежутки, имеет ширину около `2r`.
2. `pattern dose --profile … --from 0.02 --to 0.16 --count 6 -o dose.nc` — засветить и
   проявить; прямоугольник, который выглядит правильно, даёт `--power` для плат.
   Соответствие «прямоугольник, снизу вверх → y, мощность, S» печатается и пишется в
   шапку.
3. `pattern square --profile … --power 0.05 -o square.nc` — засветить, затем измерить
   штангенциркулем обе диагонали и обе стороны. `d1` — от переднего левого угла к
   заднему правому, `d2` — от переднего правого к заднему левому, и
   `theta = (d1 - d2) / (√2 · L)`, где `L` ИЗМЕРЕНА, а не номинальная. Команда печатает
   формулы с уже подставленными текущими числами:
   `scale_x = measured X side / 150.000 mm`, `skew_deg = theta`.
4. Записать их в `profiles/<имя>.calibration.toml` с `measured = YYYY-MM-DD`.
5. Проверить: `pattern square … --with-calibration` рисует квадрат ЧЕРЕЗ калибровку и
   печатает `scale_x_new = 1.002000 * (measured X side / 150.000 mm)`,
   `skew_new = 0.1000 deg + theta`. Масштаб — коэффициент, поэтому умножается; перекос —
   угол, поэтому складывается.

6. `pattern grid --profile … --power 0.05 --width-mm 50 --height-mm 40 --line-mm 0.2
   --gap-mm 0.15 -o grid.nc` — тест ПОКРЫТИЯ, а не замер: прямоугольник заполняется
   линиями, и засвечивается сразу вся рабочая площадь, так что проявку видно на
   квадратных сантиметрах, а не на одной полоске. `--direction both|x|y` выбирает линии
   вдоль Y, вдоль X или и те и другие. Первая линия — вплотную к ближнему краю, остаток
   у дальнего края — промежуток. Линия ВДОЛЬ X — это полоса строк, поэтому её ширина и
   промежуток над ней округляются к шагу строк (`scan.row_step_um`): команда называет
   обе ширины, которые получатся на самом деле (0.21 мм при шаге 0.025 — это 0.200 или
   0.225), и печатает, сколько линий легло по каждой оси.

Квадрат игнорирует масштабы и перекос профиля, если не задан `--with-calibration`: он
их МЕРЯЕТ, а измерение величины через саму себя даёт остаток, а не величину. Все четыре
шаблона идут без компенсации пятна, если не задан `--with-compensation`: штрихи — то,
по чему пятно и МЕРЯЮТ, а сетка, нарисованная через неизмеренный радиус, скрыла бы
ровно то, ради чего она и нужна.

**Полоска дозы ПО СКОРОСТИ.** Когда дозу задаёт не слово мощности, а скорость движения
головки — лазер, который умеет только включаться и выключаться, — полоска меняет скорость
и держит ОДНУ мощность:

    gerber2ldi pattern dose --profile P --speeds 80,57,40,28,20,14,10,7,5 --power P -o dose.nc
    gerber2ldi pattern dose --profile P --speed-from 80 --speed-to 5 --count 9 --power P -o dose.nc

Прямоугольники идут снизу вверх с УБЫВАЮЩЕЙ скоростью, поэтому доза РАСТЁТ; равные соседи —
отказ, потому что две плитки, которые нельзя отличить друг от друга, это зря потраченная
засветка. Мощности и скорости в одной команде тоже отказ: одна ручка на полоску. По каждой
плитке команда печатает `S`, скорость и ОТНОСИТЕЛЬНУЮ дозу (`мощность × скорость профиля /
скорость строки`, то есть 1.0 везде, где скорость равна профильной), а если `laser.power_w`
измерена — ещё и абсолютную поверхностную дозу
`E = 1e5 · P[Вт] · мощность / (v[мм/с] · Δy[мм])` в мДж/см². При `power_w = 0` печатается
`абсолютная доза неизвестна`: число, которое никто не мерил, хуже, чем никакого.

Каждая скорость проверяется по станку ДО того, как появится хоть байт программы:
`machine.max_rate_x_mm_s` (`$110`/60) и `machine.accel_x_mm_s2` (`$120`). Скорость выше
предела — отказ: GRBL молча срежет `F`, и доза выйдет больше заявленной; полоса короче
`v²/(2a)` — тоже отказ: первая медь светилась бы, пока головка ещё разгоняется.

Рядом с каждой плиткой записывай: ток драйвера, показание фотодиода (если он есть), и
проявку (концентрация, температура, время) плюс как сушили слой. Доза сравнима с другой
дозой только когда это стоит в одной строке.

### 10. Если что-то не так

| симптом | вероятная причина | что делать |
|---|---|---|
| края и места смены мощности пересвечены, «ступеньки» вдоль линии | нет лазерного режима: GRBL стоит на каждой смене `S` | `$32=1` |
| мощность почти не влияет, всё слабо или всё передержано | `$30` ≠ `laser.s_max` | выставить `$30` по профилю |
| засветилась не та сторона | `--side` | `top` для стороны, которую рисуете первой, `bottom` для зеркальной |
| рисунок на краю стола или за ним | не выставлен рабочий ноль или нет `--place` | `G10 L20 P1 X0 Y0` в углу `front-left`, либо `--place X,Y` |
| дорожки толще нарисованных, промежутки слиплись | нет компенсации или неверный `spot_radius_um` | перемерить `bars`, вписать радиус |
| стороны не совпадают | нет общей рамки (`--frame`), заготовка сдвинулась между прогонами, неверный знак `skew_deg` или масштаб | одна `--frame` и один `--place` на обе стороны, один упор для заготовки; затем `pattern square --with-calibration` и взять напечатанные формулы |
| не засветилось вообще ничего | старый файл без `M4` после `G0` | пересобрать; сверить с образцом ниже |

Правильный проход выглядит так (первые строки любого `.nc`):

```
M5
G0 X0 Y0
M4 S0
G1 X5.09 S0
G1 X80.821 S600
```

## Как читать шапку .nc

```
; requires GRBL laser mode $32=1
; work coordinates G54: the operator sets the work zero at the table corner named by profile.table.origin (front-left)
; spot compensation: off
; calibration in force: scale_x=1.002000 scale_y=0.998000 skew=0.1000 deg
; GRBL: $32=1 (laser mode), $30=1000 (max spindle speed: the power word is a fraction of it)
```

* первые две строки говорят, на что рассчитан файл: лазерный режим и рабочий ноль в
  названном углу;
* `spot compensation` — сужен ли рисунок на радиус пятна;
* `calibration in force` — какие масштаб и перекос РЕАЛЬНО применены (это НЕ значения
  из файла, если шаблон нарочно рисовал без них);
* строка `GRBL` повторяет обе настройки с `s_max` профиля: файл несёт систему, в
  которой читаются его `S`;
* шаблон добавляет свои строки: что рисует, как мерить, применена ли калибровка и
  формулы для файла калибровки.

## Координаты и отказы

Координаты в программе — рабочие координаты G54: проверка «внутри стола» верна ровно
настолько, насколько верен выставленный оператором ноль. В файле калибровки записана
ошибка станка (`scale_x`, `scale_y` — реальное/заданное, `skew_deg` положителен, когда
ось Y наклонена к +X); программа делит на масштабы и сдвигает каждую строку на
`−y·tg(skew)`.

`job` отказывает, а не подгоняет: мощность выше потолка, рисунок, не влезающий на стол
с разгоном, пятно без замера без `--no-spot-compensation`, неизвестное начало координат
стола, ось сканирования не X. Предупреждения — неоткалиброванный станок, период ШИМ
крупнее пятна — строки в stderr, без окон.

Геометрия берётся прямо из гербера — промежуточного растра в конвейере нет, а TIFF
нужен только глазам. Везде миллиметры, по X ничего не дискретизируется (это решает
станок), строка снимается по центру проезда: `y0 + (i + 0.5) · step_y`.

## MSLA-принтер: тестовые маски

Тот же резист засвечивается и на MSLA-принтере (ЖК-маска + УФ 405 нм). Там маска — это
всё: экран засвечивает ЦЕЛЫЕ пиксели, поэтому тестовый рисунок надо рисовать в пикселях
и честно говорить, какой стала запрошенная ширина. Это делает `tools/msla_tests.py`; к
лазерной цепочке он не относится и пакет не импортирует.

```sh
.venv/bin/python tools/msla_tests.py bars --screen-px 5760x3600 --pixel-um 34x34 \
    -o out/bars.png --widths-px 6,5,4,3,2,1
.venv/bin/python tools/msla_tests.py grid --screen-px 5760x3600 --pixel-um 34x34 \
    -o out/grid.png --width-mm 50 --height-mm 40 --line-px 6 --gap-px 4
```

`--widths-px 6,5,4,3,2,1` — та полоска, с которой стоит начинать на этом экране: шесть РАЗНЫХ
ступеней по 34 мкм (6 px = 204, 5 = 170, 4 = 136, 3 = 102, 2 = 68, 1 = 34 мкм). Список в
миллиметрах 0.2/0.15/0.1/0.08/0.06/0.05 дал бы 6, 4, 3, 2, 2, 1 — две одинаковые группы, о чём
скрипт и предупреждает.

* `--screen-px` и `--pixel-um` **обязательны**: выдуманное число хуже отказа. Для Anycubic
  Photon Mono X 6Ks профиль принтера в UVtools (и `Anycubic Photon Mono X 6Ks.ini` от
  PrusaSlicer) говорит 195.84 × 122.4 мм на 5760 × 3600 px, то есть **34 мкм на
  пиксель** — это профиль, а не проверенный паспорт. Пиксель может быть неквадратным —
  две величины, по оси.
* каждая ширина становится `n = round(ширина / шаг)` пикселей СВОЕЙ оси, и отчёт печатает
  запрошенную ширину рядом с ФАКТИЧЕСКОЙ: 0.100 мм на пикселе 34 мкм — это 3 px =
  0.102 мм, а 0.080 мм — 2 px = 0.068 мм. Именно фактическое число и будет на пластине.
* каждый рисунок несёт букву **F** в своём верхнем левом углу (2 мм, линии 3 px), а узор
  начинается правее неё: F несимметрична по обеим осям, поэтому зеркальная засветка
  (ножка справа) или перевёрнутая (перекладины внизу) видна на пластине без микроскопа.
  `--no-marker` выключает метку.
* ширина меньше половины пикселя — отказ; две ширины, давшие одно `n`, объявляются: их
  группы на пластине будут одинаковыми;
* ширину можно заказать в миллиметрах или в ЦЕЛЫХ ПИКСЕЛЯХ (`--widths-px`, `--line-px`,
  `--gap-px`); эти две формы исключают друг друга. Пиксели — это ровно то, что будет
  нарисовано: `n` пикселей КАЖДОЙ оси, поэтому на неквадратном пикселе одно число — две
  физические ширины;
* заказ в миллиметрах рисуется по ближайшему целому пикселю, и если промах больше 10 %,
  скрипт это говорит: «0.050 mm along Y is drawn as 34.0 um (-32 %)». У пиксельной формы
  такого предупреждения нет: отклоняться не от чего.
* `bars` — группы линий с промежутком, равным ширине: горизонтальный блок (разрешение по
  Y) и вертикальный (разрешение по X), каждый квадратный, чтобы оси были сравнимы;
* `grid` — прямоугольник, заполненный линиями: первая линия вплотную к ближнему краю,
  линия только целиком, остаток у дальнего края — промежуток;
* белое — засвеченный пиксель: по умолчанию белые ЛИНИИ, `--invert` меняет это местами, а
  `--mirror` отражает готовую картинку по X для резиста лицом к экрану;
* отчёт — экран, пиксель, ширины запрошенные и фактические, зеркало, полярность — пишется
  ещё и в текстовый кусок PNG `msla_tests`, чтобы файл помнил, что он такое.

Как довезти PNG до принтера (путь со слов Claude, Денис ещё не проверял): открыть в
**UVtools** любой однослойный файл этого принтера (сгодится сделанный слайсером),
заменить слой импортированной картинкой, выставить время засветки и сохранить. Маска
задаёт геометрию, время засветки — дозу.

## Известные особенности библиотек, которые обходим

`Rectangle.to_arc_poly()` в gerbonara возвращает рамку повёрнутого прямоугольника,
поэтому прямоугольники строятся по углам; pygerber не поворачивает макрос-примитив 5,
